# review-repo-security — source & influences

Prompted by a whole-repository security review of `bbmon` on 2026-08-13, which found what a diff-scoped review structurally cannot: identifying data committed days earlier, a real routable address used as a documentation example, and an sshd drop-in that was configured but not in force.

The commit-provenance step arrives separately, from a bbmon exposure of 2026-08-15: a commit reaching `main` could reach a running system, and the branch-side control that would have contained it was unavailable there. It was parked as an always-on tripwire and re-decided on 2026-08-16 as a step here, where a trigger already exists. No unexpected commit ever appeared, and the route has since been closed.

The standalone-session non-negotiable does not come from the review's own content. It comes from session-size evidence measured 2026-08-15 across 46 non-trivial sessions. Counting only those after the *make every content change visible* non-negotiable landed, the only sessions ever to break it were the two largest ever run — 291 and 612 assistant turns, four violations between them — against some forty smaller ones that were clean. The larger opened as implementation work, then spent 21 of its 22 hours on an unrelated whole-repository security review. That measurement lived in `learning/INBOX.md` until the entry closed on 2026-08-16; `git log -S` over that file recovers it.
